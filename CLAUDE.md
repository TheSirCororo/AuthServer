# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

AuthServer is a Kotlin/JVM Minecraft authentication limbo supporting every Java release **1.8 - 26.3** natively
(`ProtocolVersion` enum), with licensed (Mojang) and offline (password) accounts, a Velocity plugin for routing,
loadable maps and a jar plugin API. `README.md` covers features and setup.

## Commands

JDK 25 is required (`export JAVA_HOME=/usr/lib/jvm/java-25`); use the wrapper.

```sh
./gradlew build                                   # all modules + all tests
./gradlew :server:test --tests '*StandaloneAuthTest*'
./gradlew :protocol:test --tests '*PacketRegistryTest.ids match*'
./gradlew :server:shadowJar :velocity:shadowJar   # runnable server jar, Velocity plugin jar
./gradlew :probe:installDist                      # tools/probe client used by the scripts below
tools/stand/stand.py up --accept-eula             # local Velocity + auth + Paper stand in run/stand
```

No linter/formatter; official Kotlin style. JUnit silently skips test methods that return a value, so Kotlin tests
must use block bodies, not `fun x() = foo.use { ... }`.

## Architecture

Modules (dependencies point downwards): `protocol` <- `gamedata` <- `world`; `storage`; `bridge` (Java, no deps);
`api` (-> protocol, bridge); `server` (everything); `velocity` (Java, -> bridge); `tools/probe` (-> protocol);
`plugin-processor` (Java APT, no deps) <- `plugin-ksp`; `examples/example-plugin` (-> api, built with KSP and
loaded as a real plugin jar by `ExamplePluginTest`). Shared build config is in `build-logic` convention plugins
(`authserver.kotlin-conventions`, `authserver.plugin-conventions` for plugins, ...) and `gradle/libs.versions.toml`.

**Protocol.** Packets are version-independent models; each `PacketCodec` branches on `ProtocolVersion`
(comparable by release order). `MinecraftPackets.registry` binds models to IDs per (version, state, direction).
Play/configuration IDs come from the **generated** `protocol/src/main/resources/.../packet-ids.txt`; never edit it,
regenerate with `tools/vanilla/packet_table.py`. One model may map to different packets per version (titles and
the action bar share `set_titles` before 1.17; those registrations use `decodes = false`). Components are JSON
before 1.20.3 and NBT after (`buffer/Components.kt`); bit sets changed encoding in 26.3.

**Game data.** `gamedata` resources (`<protocol>/version.properties`, registries, tags, block/item mappings) are
generated by `tools/vanilla/gamedata.py` from official servers: block states of every release are upgraded with
Mojang's DataFixer and inverted; canonical IDs are the newest release's. `GameData.version(v)` loads lazily.

**World.** `World` stores canonical states; `ChunkEncoder(version)` produces the version's chunk (+ light) packets,
driven by `ChunkFormat` flags. `ChunkDecoder` exists to test against the vanilla fixtures in
`world/src/test/resources/vanilla-chunks` (exported by `tools/vanilla/chunk_fixtures.py`).

**Server.** Netty pipeline: `cipher` -> `frame-decoder`/`frame-encoder` -> `compression` -> `packet-codec` ->
`Connection`. `Connection.version/state/handler` are confined to the channel's event loop; state changes go through
`switchState` so a packet is encoded in the state it was sent in. Handlers per state live in `network/handler`
(`Handshake` -> `Status` | `Login` -> `Configuration` (1.20.2+) -> `Play`). Clientbound packets missing in a version
are dropped by `PacketCodec` with a successful promise. Player logic runs in `LimboPlayer.scope`, a sequential
coroutine per player on I/O threads; `AuthManager` holds the authentication rules and implements the API's
`AuthService`. `LoginInterface` gives the help item and the licensed/offline choice menu; inventory and menu
state lives in `LimboPlayer`, item encoding per version in `protocol/.../buffer/Items.kt` (menu and data component
IDs come from the generated `registry-ids.txt`). `AuthServerImpl` wires everything and owns the lifecycle.
`storage/.../importer/AccountImporter` imports other plugins' databases; legacy hash formats are in
`LegacyHashes`. Login mode: `PremiumResolver.status` is asked once per connection (standalone login or the proxy's
pre-login via `ProxyApi`); under the default `MANUAL` policy a licensed choice is an in-memory, one-shot
`LicensedLoginRequests` entry, and the premium account is created only in `AuthManager.onJoin` after Mojang verified
the player. Behind Velocity the choice travels as a `BridgeMessage.LicensedLogin` and the plugin transfers or
disconnects the player. Two-factor authentication and email live in `auth/security`: `AccountSecurity` implements
`/email` and `/2fa` for a `SecurityActor` (a `LimboPlayer`, or a player on another server through `ProxyApi`'s
`/command` route) and holds the in-memory `EmailCodes`; `AuthManager.passFirstFactor` turns a password, Mojang or
recovery login into a `/code` step. Mail goes through the `MailSender` interface (`SmtpMailSender`; tests use
`FakeMail` from `TestHarness`).

**Proxy.** Forwarding (`network/Forwarding.kt`) sets the real address and UUID; an offline-UUID means an offline
account. After authentication the server sends a `bridge` message signed with `proxy.secret` on
`authserver:bridge`; the Velocity plugin (`velocity/.../AuthListener`) trusts only signed messages from the auth
server's backend connection, blocks other servers until then and never lets an auth-server kick fall back.
`ProxyApi` (JDK HttpServer, `X-AuthServer-Secret` header) tells the plugin at pre-login whether a name must use
Mojang and serves the plugin's `/changepassword` and `/logout` (routes in `bridge/.../AccountApi`).

## Verification tooling

`tools/vanilla` (Python + single-file Java run on official server classpaths) downloads releases into
`~/.cache/authserver/vanilla`, runs data generators, records vanilla sessions with the probe (`probe.py
--accept-eula` starts throw-away vanilla servers) and regenerates data. After protocol changes run
`probe verify <protocol> ~/.cache/authserver/vanilla/<release>/recording` for all releases (see README) - it must
report no problems. Byte-exact round trips can hide wrong field semantics (26.3's optional game mode looked
like a byte), so also compare against a real consumer when changing a packet: `tools/velocity/e2e.py` runs a real
Velocity proxy end to end, the stand adds Paper. CI (`.github/workflows/ci.yml`) builds and tests; on master it
pushes the Docker image to GHCR and creates a `v<version>-build.<n>` tag and release with the jars.
